## 1. 项目要做什么

一个跑在 ONOS 之上的「网络大脑」：周期性通过北向 REST 拉取拓扑 → 存成图 → 比对出变化 → 用 Dijkstra 算路径 → 把流表下发回数据平面。

答辩笔记里列的功能，按优先级排：

| # | 功能 | 状态 |
|---|---|---|
| 1 | 周期性调用 controller 接口，感知拓扑（devices / links / hosts） | 必做 |
| 2 | 拓扑在大脑里用图结构承载（邻接表） | 必做 |
| 3 | 两轮拓扑比对，记录差异（增 / 删 / 改 + 主机迁移） | 必做 |
| 4 | 单通信对 Dijkstra 算最优路径，下发流表到数据平面 | 必做 |
| 5 | 拓扑变化后自适应重算受影响路径 | 必做 |
| 6 | 多通信对各自独立计算与更新 | 必做 |
| 7 | 单源多目的组播：最短路径树 + 组表复制 | 拓展 |
| 8 | 组播需求感知：REST 手动保底 → ONOS Java 应用接 IGMP | 拓展 |
| 9 | 前端可视化（HTML + WebSocket 实时刷新） | 加分 |

## 4. 北向接口清单（实验⑥⑦原文，可直接照抄）

```
认证：HTTPBasicAuth("karaf", "karaf")      ← 不是 GUI 的 onos/rocks
头：  {"Accept": "application/json"}

GET  /onos/v1/devices                     所有交换机
GET  /onos/v1/hosts                       所有主机
GET  /onos/v1/links                       所有链路（双向各报一次）
GET  /onos/v1/flows/{deviceId}            某台交换机的流表
POST /onos/v1/flows/{deviceId}?appId=xxx  下发流表（appId 是查询参数，不是 body）
DELETE /onos/v1/flows/{deviceId}/{flowId} 精确删一条
DELETE /onos/v1/flows/application/{appId} 按应用批量删（本项目禁用，会误删）
POST /onos/v1/devices/{id}/portstate/{portId}   body {"enabled": false}  制造链路故障
```

流表 JSON 结构（实验⑦ 5.2.2）：

```json
{
  "priority": 40000, "timeout": 0, "isPermanent": true,
  "deviceId": "of:0000000000000001",
  "selector":  {"criteria": [{"type": "IN_PORT", "port": "1"}]},
  "treatment": {"instructions": [{"type": "OUTPUT", "port": "2"}]}
}
```

## 7. 已知坑（血泪，直接照做）

1. **REST 以前测出「全 404」是错的**。当时用的是 GUI 凭据 `onos/rocks`，而 REST 要用 `karaf/karaf`。实验⑦ 原文明确 `http://localhost:8181/onos/v1/devices` 返回 200。**新对话第一步就重测这一条**。
2. **`GET /hosts` 的 `host["id"]` 是 `MAC/VLAN`**（如 `00:00:00:00:00:06/None`），**不是 IP**。IP 在 `ipAddresses` 字段里。
3. **主机没发过包时 `ipAddresses` 是空的** → 必须先 `pingall` 再拉拓扑。
4. **`/links` 会把一条物理链路按两个方向各返回一次** → 存图用有向，做 diff 必须 `frozenset({u,v})` 归一化。
5. **`locations` 里同时有 `elementId` 和 `port`** → 判断主机迁移必须两项都比。
6. **`appId` 是查询参数**（`params={"appId": ...}`），不是 body 字段。
7. **所有通信对共用一个 appId → 不能按 appId 批量删**，必须按 `flowId` 精确删，所以要维护映射表。
8. **`fwd` 必须关掉**：`app deactivate org.onosproject.fwd`。关掉后网络应该立刻不通——还通就是没关干净。
9. **Packet-In 需要前提**：交换机上有 table-miss 动作把未命中流量送控制器，控制器侧声明接收该类报文。不是无条件上送。
10. **`iperf` 不发 IGMP**。发成员报告的是主机内核 socket 加入组（`IP_ADD_MEMBERSHIP`）。

## 8. 建议的开发顺序（一次只推进一步）

**第 1 步 · 打通 REST（今天的唯一目标）**

```bash
# 终端 A：起拓扑
sudo mn --topo=single,3 --controller=remote,ip=127.0.0.1,port=6653 --mac --switch=ovs,protocols=OpenFlow13
# 在 mininet 里
pingall

# 终端 B：验证 REST
python3 -c "
import requests
from requests.auth import HTTPBasicAuth
r = requests.get('http://127.0.0.1:8181/onos/v1/devices',
                 headers={'Accept':'application/json'},
                 auth=HTTPBasicAuth('karaf','karaf'))
print(r.status_code); print(r.text[:300])"
```

期望 `200` + 设备 JSON。若 `401` 查认证，若 `404` 先确认容器在跑、端口映射在。

**第 2 步**：拉 devices/links/hosts，建邻接表 + 主机表，打印出来核对。
**第 3 步**：Dijkstra 算一条路径，`print` 出交换机序列和每跳出端口。
**第 4 步**：构流表 JSON，`POST` 下发，`ping` 验证，`dump-flows` 核对。
**第 5 步**：加周期轮询 + 快照 diff + 变化日志。
**第 6 步**：自适应重算 + flowId 映射表 + 先下新再删旧。
**第 7 步**：组播（SPT + 组表）。
**第 8 步**：前端 HTML + WebSocket。

代码骨架建议：

```
brain/
  main.py     Sanic app、路由、启动钩子里挂轮询任务
  onos.py     REST 客户端（fetch_devices / fetch_links / fetch_hosts / post_flow / delete_flow）
  topo.py     build_graph / build_host_table / snapshot / diff
  path.py     dijkstra / multicast_tree
  flow.py     path_to_flows / install_path / uninstall_path
  static/index.html
```
