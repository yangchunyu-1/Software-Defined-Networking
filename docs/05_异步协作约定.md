# 异步协作约定

> **本文件解决的问题**：三个人不在同一时间干活，也凑不出共同的整块时间。
> 所以「分歧靠临时开会解决」不可行——必须把**同步点前移**：能写进文档就不口头讲，能写成测试就不靠联调。
>
> 读者：三名成员 + 各自的 AI 助手。
> 状态：v1.0，2026-10-29 起生效。

---

## 0. 节奏

**项目截止是期末，不是竞赛截止。每周四晚碰头一次，其余时间全部异步。**

| 场合 | 什么时候 | 干什么 | 不干什么 |
|---|---|---|---|
| 周四碰头 | 每周四晚 | 过闸门、定接口、分本周任务、处理卡点 | **不写代码、不联调**——碰头是决策会，不是干活会 |
| 日常异步 | 其余时间 | 各自按任务书推进，用 PR + Issue 交流 | 不等人回消息才干活 |

**推论：一周只有一个同步点，所以一次没碰成就要等七天。**
因此每周四必须做到：① 上闸门的产出**已经贴在 PR 里**（不是口头说做完了）；② 本周分歧**当天定死**，
不能留「下周再说」；③ 没定下来的，**当场降级为「按文档现有写法先做」**，不许悬空。

---

## 1. 唯一的原则：把同步点前移

> **能在文档里说清的，不开会；能写成测试的，不靠联调。**

| 依赖形式 | 同步协作（旧） | 异步协作（新） |
|---|---|---|
| A 的产出是 B 的输入 | B 等 A 做完 | A 先把**格式/签名**写进 `02`，B 按格式造数据先开工 |
| 两人接口不一致 | 联调时发现 | 各写一份**契约测试**，CI 跑出来就发现 |
| 设计分歧 | 群里讨论半小时 | 在 `02` 提 PR，diff 就是方案，评论就是讨论 |
| 进度确认 | 站会上说「做完了」 | PR 里贴**真实命令 + 真实输出**，没贴就是没做 |

---

## 2. 样本契约：格式先定，内容后补

`docs/02` 第 4 节已经定死 `graph` / `host_table` / `snapshot` / `deployed` 的结构。
**这就是格式契约。** 有了它，没有人需要等真实 ONOS 响应才能写代码。

```
brain/tests/fixtures/          ← 手写 / 生成的样本，入库，所有人共用
├── topo_tree22.py             3 交换机 4 主机（tree,2,2），结构照 02
├── topo_chain3.py             3 跳直线，最短路只有一条，便于断言
└── links_broken.json          删掉一条物理链路（两个方向都删）
```

**规则：**

1. **fixture 只能包含 `02` 定义过的字段**。多一个字段 = 契约变更，要走第 5 节流程。
2. **fixture 里的 dpid 统一用 `of:0000000000000001` 起**，不用随机值——这样日志和断言能直接对。
3. **真样本到位后替换 fixture，测试代码一行不改。** 如果替换后测试红了，说明 fixture 和真实响应结构不一致
   ——那是发现得早，不是坏事。
4. `samples/`（真实响应）和 `tests/fixtures/`（手写样本）**分开存**，不要混。前者是证据，后者是脚手架。

## 3. 契约测试：代替联调

每个人为自己的模块写一个测试，**入参必须严格按 `02` 造**。三个人的测试全绿，就等价于「接口对上了」。

| 谁 | 测试文件 | 断言什么 |
|---|---|---|
| 甲 | `tests/test_topo.py` | 喂 `fixtures` → `len(graph)` == 交换机数；反向边 `sport` 不同；断一条边 → `edges_removed` 长度 == 1 |
| 乙 | `tests/test_path.py` | 喂 `fixtures` 的 `graph` → `dijkstra` 出参 `{path, cost, out_ports}`，`len(out_ports) == len(path)-1`；`src==dst` 返回单元素；不可达返回 `None` |
| 乙 | `tests/test_flow.py` | `path_to_flows` 出参条数 == `len(path)`；首跳 `IN_PORT == src_host["port"]`；末跳 `OUTPUT == dst_host["port"]` |
| 丙 | `tests/test_api.py` | `TestClient` 喂假 `app.ctx` → `/api/state` 14 个字段齐；`/api/route` 出参形状符合 §6 |

**跑测试的方式（三人一致）：**

```bash
cd brain && python3 -m pytest tests/ -q
```

**约定：**

- 测试**不许连 ONOS**。连了就不是契约测试，是集成测试，放在 N4 之后。
- 测试**不许依赖执行顺序**。每个测试自己造 `app.ctx`，不共享全局状态。
- **红了不许跳过**（`@pytest.mark.skip` 要写明关联 Issue）。

## 4. 分支与 PR

三个人各开一条分支，**不直接往 `main` 提交**。

| 人 | 建议分支名 | 谁的文件 |
|---|---|---|
| 甲 | `fish-perception-layer` | `config.py` `onos.py` `onos_async.py` `topo.py` `samples/` `tests/test_topo.py` |
| 乙 | `dev-decision-layer` | `path.py` `flow.py` `group.py` `tests/test_path.py` `tests/test_flow.py` |
| 丙 | `dev-app-layer` | `main.py` `static/` `run.sh` `tests/test_api.py` |

> 分支名**用纯 ASCII 单层名**，不带斜杠、不带中文。

**PR 规则：**

| 项 | 要求 |
|---|---|
| 一个 PR 只做一件事 | 对应任务书里的一个步骤（如 `乙-1`），不做「顺手改了一堆」 |
| PR 描述必须包含 | ① 对应任务书编号 ② **真实命令 + 真实输出** ③ 还没把握的地方（标 `❓`） |
| 谁来 review | **改动谁的文件，谁 review**（改别人的接口 = 必须对方同意）；其余人可看可评 |
| review 时效 | 48 小时内必须给意见，哪怕是「看过了没问题」。超时视为默许，但**合并前仍需一句回复** |
| 合并方式 | Squash merge，保持 `main` 一条直线 |
| 谁合并 | **作者自己合并**（在自己的评审通过后），不需要管理员 |

**「贴真实输出」是硬性要求**：说「dijkstra 写好了」不算；贴 `pytest tests/test_path.py -q` 的通过输出才算。

## 5. 分歧处理：文档优先（与同步耗时无关）

`docs/02` 第 8 节的流程保留，**只是把「等 30 分钟」改成「等下一个确认点」**：

1. 想改接口的人**先提 PR 改 `docs/02`**，PR 描述里写清：改什么、为什么必须改、影响谁的代码。
2. 拉另外两人 review。**48 小时内**必须有人回复同意或反对。
3. 反对 → 在 PR 里讨论出结论，不上群聊。
4. 48 小时无人反对 → **按 PR 内容执行**，PR 合并即生效。
5. **紧急口子**：如果不改就没法继续干活（被卡死），作者可以**先按自己的方案写代码**，
   但必须在 PR 里写明「我按 X 方案先做了，如果不同意请明天内提出」。

**禁止**：代码先改了、文档不补。理由见 `02` §0——字段改名是静默失效，代码不会报错，只会永远筛出零条结果。

## 6. 无人值守时的三条兜底

异步开发最怕的不是分歧，是**卡住没人管**。

| 情况 | 怎么办 |
|---|---|
| 卡在环境上超过 1 小时 | 在 Issue 里贴：报错原文 + 已经试过的三条 | 
| 卡在别人的接口上 | 在 Issue 里 @ 对应的人，标注「阻塞」，**自己切去做不依赖它的部分** |
| 不确定某个字段该怎么理解 | **按 `02` 字面理解先做**，在代码里加 `# 02 §x.y 理解：...`，PR 里标出来让人确认 |

**原则：宁可先按文档做错、再改，也不要停下来等人。** 三人项目里，停下等待的代价永远大于改一行的代价。

## 7. 每周四碰头的固定议程（20 分钟走完）

```
1. 过闸门（5 min）—— 谁的 PR 还没合？闸门产出贴了吗？
2. 定接口（10 min）—— 本周有哪些 02 的 PR 待确认？当场签或当场毙
3. 分下周任务（3 min）—— 每人认领任务书编号，写进 Issue
4. 卡点（2 min）—— 谁被什么卡住了，当场给结论或指定兜底方案
```

**碰头不做的事**：不写代码、不联调、不演示。演示和联调放在日常异步时间，结果贴 PR。

---

## 8. 附：一句话记住

> **接口写进文档、样本写进 fixture、验证写成测试。三件事做完，剩下的事不需要见面。**
