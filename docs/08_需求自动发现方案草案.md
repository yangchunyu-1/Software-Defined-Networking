## 1. 背景与决策来源

| 项 | 内容 |
|---|---|
| 新要求 | 演示「应用平面**自动感知**通信需求」：主机发出首个数据包后，大脑**无人注册**即发现 (src,dst) 并算路下发（2026-11-19 老师口径） |

## 2. 方案总览

### 2.1 数据流

```
h1 首次 ping h3（无任何人工注册）
  ↓ ① 无匹配流表 → packet-in 上送控制器（插件已 requestPackets(IPv4)）
  ↓ ② DiscoveryApp（Java/OSGi）收到 packet-in，解析 Ethernet→IPv4 src/dst
  ↓ ③ 无序对 (src,dst) 去重缓存（带 TTL）命中 → 丢弃；未命中 → 继续
  ↓ ④ App 向大脑 POST /api/route {"src","dst","source":"auto"}（HTTP，容器→宿主 ❓ 见 §6 风险 2）
  ↓ ⑤ 大脑按既有链路处理：resolve_legs → dijkstra → install_path（唯一流表写入者不变）
  ↓ ⑥ 流表生效后，后续数据包直接转发，不再触发 packet-in（自然停止）
```

### 2.2 设计原则（三条，评审重点）

1. **插件只感知、不转发**：App 不装任何业务流表、不做路径决策；大脑仍是唯一流表写入者。
   `04` §1.4 核心业务规则（图是唯一事实来源）**不受影响**。
2. **单一需求入口不变**：自动发现的需求与人工注册的需求走同一个 `POST /api/route`，
   复用既有幂等守卫（409 `already_exists`）、去重、撤销逻辑。App 侧缓存只是**前置降噪**。
3. **订阅范围最小**：只 `requestPackets` IPv4（EtherType 0x0800）；ARP 不订阅（FR-07b 的流表方案管），
   LLDP/BPDU 等控制帧在解析阶段直接丢弃。

### 2.3 App 关键设计点

| 项 | 设计 | 备注 |
|---|---|---|
| 形态 | OSGi bundle，`@Component` + `Activator`，打包 `.oar` | Maven，ONOS 2.7.0 API |
| 事件注册 | `packetService.requestPackets(TrafficSelector 匹配 IPv4)`；`registerProcessor` | ONOS 据此装 table-miss→CONTROLLER |
| 去重缓存 | key = **无序对** `{src,dst}`（覆盖反向流量，双向流表 FR-07b 下反向无需二次发现）；带 TTL（暂定 30s ❓） | `ConcurrentHashMap` + 时间戳；TTL 到期才允许重发，防止 ping 洪水打爆大脑 |
| POST 失败 | 缓存条目保留（不标记成功），TTL 到期后由下一个包重试；连续失败打 log.error | 大脑挂了不丢需求，恢复后自愈 ❓ 细节实测 |
| 大脑地址 | ONOS `cfg` 子系统配置（`brain.url`，默认 `http://127.0.0.1:8000`），不硬编码 | 容器→宿主网络见 §6 风险 2 |
| HTTP 客户端 | `java.net.HttpURLConnection`（JDK 自带，**零新增依赖**） | 符合 `01` §1「依赖最少」原则 |

### 2.4 仓库与构建

```
brain/onos-app/                    ← 新增目录（甲名下，感知层延伸）
├── pom.xml                        # ONOS 2.7.0 依赖（ artifactory/central，首次需联网 ❓）
├── app.xml / features.xml         # OSGi 描述
└── src/main/java/org/sdn/brain/discovery/DiscoveryApp.java
```

构建与安装：

```bash
cd brain/onos-app && mvn clean package          # 产物 target/*.oar
# 安装（进 ONOS 容器 CLI 或 REST）
ssh -p 8101 karaf@localhost "app install --sync /path/to/*.oar && app activate org.sdn.brain.discovery"
# 配置大脑地址
cfg set org.sdn.brain.discovery brain.url http://<宿主IP>:8000
```

## 4. 新增 FR 与判据（只增号）

| 编号 | 功能 | 触发 | 输入 → 输出 | 优先级 | 怎么验（判据） |
|---|---|---|---|---|---|
| FR-21 | 需求自动发现（PacketIn 插件） | 主机发首个数据包 | packet-in → 无序对去重 → `POST /api/route` | **必须（老师口径 2026-11-19）** | 未经人工注册的两主机 `ping`：大脑日志/需求清单出现该对（`source:"auto"`）→ 流表下发 → **ping 从 100% loss 变 0% loss**；重复 ping 不产生重复需求与重复流表；FR-17 手动注册路径仍可用（降级兜底） |

> N6 扩展：App 停用（`app deactivate`）后系统退化为纯手动注册模式，演示不崩——这是「插件挂了兜底」的判据。
