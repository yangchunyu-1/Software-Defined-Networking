## 1. N0 · 范围冻结

### 1.1 做什么（10 条，每条可验）

1. 周期性（5s）从 ONOS 北向拉 `devices` / `links` / `hosts`，异常不退出
2. 把拓扑建成字典邻接表（有向，带每端的端口号），把主机建成 IP → 位置表
3. 相邻两轮快照比对，输出节点/链路/主机的增删改
4. 主机位置变化（同 IP 换了交换机**或**换了端口）能识别为「迁移」
5. 单通信对最短路径（Dijkstra），返回交换机序列 + 每跳出端口
6. 路径映射成 OpenFlow 流表并按交换机下发，下发后能回读校验
7. 流表按 `flowId` 精确删除，不影响其它通信对
8. 拓扑变化后自动筛出受影响通信对并重算改写
9. 多通信对并存，各自独立计算与更新
10. HTTP 接口对外暴露当前网络状态（供前端与现场演示调用）

### 1.2 不做什么（**都是想过并决定不做的，不是漏的**）

| 不做 | 为什么（被问就这么答） |
|---|---|
| VLAN / VXLAN 隔离 | 单租户实验环境，无隔离需求；引入 VLAN 会让 `host_table` 的 key 从 IP 变成 `IP/vlan`，收益为零 |
| QoS / 带宽调度 | `graph` 的 `weight` 字段留了口子，本期恒为 1。做真实带宽要在 Mininet 里配 `--link=tc` 再读链路速率，属于另一个题目 |
| 多控制器 / 集群高可用 | ONOS 单实例 + 大脑单实例。高可用不是本项目要证明的东西（要证明的是**北向可编程**） |
| 用户认证 / 多租户 | 本机演示，前端无登录，`/api/*` 无令牌。**这是明确的裁剪，不是遗漏** |
| 流表压缩 / 规则合并 | 一条路径一组流表，不做同 `IN_PORT` 的规则聚合。聚合会破坏「按 flowId 精确删」的可追溯性 |
| ONOS Java 应用（`.oar` / Maven） | 路线是北向 REST，应用平面在 ONOS **之外**。写 OSGi 应用是另一条技术路线 |
| IPv6 | 主机表按 IPv4 建。Mininet 默认也就 IPv4 地址 |
| 真实 IGMP 嗅探（第一期） | 组播需求用 REST 手动注册。IGMP 要写 ONOS 内部应用或抓包，成本远超收益 |
| 状态持久化（数据库） | 重启后 `deployed` 表清空，重新下发。演示时长内不需要 |
| 流量统计 / 历史曲线 | 需要周期性拉 `/flows/{id}` 的 `bytes` 字段做时序存储，与「拓扑感知 + 路径计算」是两件事 |

### 1.3 验收标准（一眼可判断，不接受「能启动」）

| # | 不算通过 | 才算通过 |
|---|---|---|
| A1 | 大脑打印「服务已启动」 | `GET /api/state` 返回的 `graph` 节点数 **== `ovs-vsctl list-br` 看到的交换机数**（3 台拓扑就是 3） |
| A2 | 算路接口返回 200 | 前端触发 `h1 → h3` 后，`ping` 从 100% loss 变成 **0% loss**，且 `ovs-ofctl dump-flows` 能看到对应规则 |
| A3 | diff 有输出 | 断一条链路后，`/api/diff` 的 `edges_removed` 长度 **== 1**（不是 2、不是 0） |
| A4 | 断链后还能 ping 通 | 从断链到 `ping` 恢复的连接中断时间 **< 10s**，且日志里有 `recompute` 行 |
| A5 | 两对主机各自能 ping | 两对**同时** `ping` 时都通，且删掉其中一对的流表后另一对**不受影响** |
| A6 | 组播"发出去了" | 两个接收者进程**都**收到数据包，`dump-flows` 里能看到 `group_id` |

### 1.4 核心业务规则（一句话，全项目围绕它）

> **大脑持有的拓扑图是唯一事实来源：任何一条已下发的流，其下一跳必须与当前图一致；图变了，受影响流必须在下一次轮询内被改写为新图上的最短路。**

这条规则推出三个硬推论，写代码时随时对照：

1. **先下新、再删旧**——否则在「删旧」和「下新」之间网络是断的，违反「一致」。
2. **下发失败必须回滚**——留一条指向旧路径的流，就等于图与流不一致。
3. **`deployed` 表里没有记录 = 这条流不存在**——不允许有「下了但没记住」的流，那一定删不掉。

## 2. N1 · 功能需求（FR）

| 编号 | 功能 | 触发 | 输入 → 输出 | 优先级 | 怎么验（判据） |
|---|---|---|---|---|---|
| FR-01 | 周期拓扑感知 | 定时 5s | ONOS 三端点 → 原始 JSON×3 | 必须 | `/api/state.poll_count` 持续增长；`docker stop onos` 后进程不退出 |
| FR-02 | 邻接表建图 | 随 FR-01 | `links[]` → `graph` | 必须 | `len(graph) == 交换机数`；每条边 `sport` 与 `links` 里 `src.port` 一致 |
| FR-03 | 主机表构建 | 随 FR-01 | `hosts[]` → `host_table` | 必须 | `pingall` 后 `len(host_table) == 主机数`；空 IP 主机有 WARNING |
| FR-04 | 拓扑差异检测 | 图变化时 | 两轮 `snapshot` → `diff` | 必须 | 断 1 条链路 → `edges_removed` 长度 == 1 |
| FR-05 | 主机迁移识别 | 位置变化时 | 两轮 `snapshot` → `hosts_moved` | 必须 | 单测：同 IP 不同 `(dpid,port)` → `hosts_moved` 命中，且 `hosts_added/removed` **均不出现**该 IP |
| FR-06 | 单对最短路径 | 人工/API | `graph, src, dst` → `{path, cost, out_ports}` | 必须 | 三跳拓扑：`len(out_ports) == len(path)-1`；`src==dst` 返回单元素 |
| FR-07 | 路径 → 流表映射 | 随 FR-06 | `res, src_host, dst_host` → `[(dpid, flow)]` | 必须 | 流表条数 == `len(path)`；首跳 `IN_PORT == src_host.port`；末跳 `OUTPUT == dst_host.port` |
| FR-08 | 流表下发与校验 | 随 FR-07 | `flow[]` → ONOS → `flowId[]` | 必须 | `ping` 通 **且** `dump-flows` 有规则 **且** 每条流都在 `deployed` 里查到 id |
| FR-09 | 流表精确删除 | 人工/API | `flowId[]` → 删除结果 | 必须 | 删后该对 `ping` 不通，**另一对仍通** |
| FR-10 | 拓扑变化自适应重算 | `diff.changed` | `diff + deployed` → 改写记录 | 必须 | 断链 → 10s 内 ping 恢复；日志有 `recompute`；未受影响的 pair 不被重下 |
| FR-11 | 多通信对并存 | 人工/API | 多组 `(src,dst)` → 互不干扰 | 必须 | 两对同时 ping 全通；删一对后另一对不掉包 |
| FR-12 | 状态查询接口 | 人工/API | — → `/api/state` JSON | 必须 | 字段清单见 `02` 第 6 节，且含 NF 反推出的全部字段 |
| FR-13 | 前端拓扑可视化 | 打开页面 | `/api/state` → 图 | 可选 | 浏览器能看到 3 个交换机节点 + 链路 + 4 台主机 |
| FR-14 | WebSocket 实时推送 | 图变化时 | `diff` → 前端 | 可选 | 不刷新页面，断链后 10s 内前端变红 |
| FR-15 | 单源多目的组播 | 人工/API | `src, dsts[]` → SPT + 组表 | 可选 | 两接收者都收到；`dump-flows` 有 `group_id` |
| FR-16 | 组播需求注册（REST） | 人工 | `POST /api/multicast` → 组表 | 可选 | 接口返回 `ok`，`ovs-ofctl dump-groups` 能查到 |

**可选簇的执行顺序**：`FR-13 → FR-14 → FR-15 → FR-16`。必须项（FR-01~12）**全部**通过验收前，不开工可选簇。

> FR-05 的说明：现场演示主机迁移成本很高（要在 Mininet 里把 veth 拔了插到另一台交换机），
> **所以 FR-05 的验收走单元测试**（构造两份 `hosts.json`），现场演示用「链路故障」代替。
> 这一条要主动说明，不要假装现场演过。

## 3. N1 · 非功能需求（NF）

每条都问过一句：**「这条需要一个接口或一个字段来支撑吗？」** —— 问出来的就是 3.1 那张表。

| 编号 | 指标 | 怎么验 | 需要接口支持吗 |
|---|---|---|---|
| NF-01 | 拓扑变化感知延迟 **< 10s**（轮询 5s + 处理） | 断链打时间戳，看 `/api/state.last_poll_ts` 与断链时刻差 | ✅ `/api/state` 要有 `last_poll_ts`、`poll_count` |
| NF-02 | 轮询期间 WebSocket 推送延迟 **< 500ms** | 开 3 个 WS 客户端，断链后测到达时间 | ✅ 要有 `ws_clients`、`push_count` |
| NF-03 | ONOS 不可用时大脑**不崩**，恢复后自愈 | `docker stop onos` → 等 60s → `docker start onos` → 等 15s → 查 `/api/state` | ✅ 要有 `onos_ok`、`onos_errors`、`last_error` |
| NF-04 | 单轮轮询耗时 **< 1s**（3 台交换机） | 日志里 `poll ok ... in XXms`；`/api/state.poll_ms` | ✅ 要有 `poll_ms` |
| NF-05 | 连续跑 **1000 轮内存不持续增长** | 每 100 轮 `ps -o rss=` 一次，比较首尾 | ❌ 但**日志必须轮转**（别写满磁盘） |
| NF-06 | 前端**零外网依赖**：断网也能用 | `grep -nE "https?://" static/index.html` 应无非注释命中；断开代理后刷新页面 | ❌ 靠约定 |
| NF-07 | 关键动作全部有日志且带对象 id | 日志里能 `grep` 到 6 类事件：`poll_ok` `diff` `route` `install` `delete` `recompute` | ❌ 靠日志格式约定 |

  "push_count":   57,             // NF-02

## 4. 验证命令手册（每条命令的结果就是「怎么验」的答案）

> 演示拓扑统一用 `tree,2,2`（3 台交换机 + 4 台主机），dpid 与 `s1/s2/s3` 的对应关系**以 `ovs-ofctl show` 实测为准**（尚未实测，见 README TBD 表）。
> 端口号同理，下面命令里的 `3` 是占位，实测时替换。

### A1 · 拓扑感知（FR-01/02/03）

```bash
curl -s localhost:8000/api/state | python3 -c "import json,sys;d=json.load(sys.stdin);print(len(d['graph']),'switches',len(d['hosts']),'hosts')"
```
判据：`3 switches 4 hosts`。

### A3 · 差异检测（FR-04）

```bash
curl -s -u karaf:karaf -X POST -H 'Content-Type: application/json' \
  -d '{"enabled":false}' \
  http://127.0.0.1:8181/onos/v1/devices/of:0000000000000001/portstate/3
sleep 7
curl -s localhost:8000/api/diff | python3 -c "import json,sys;d=json.load(sys.stdin);print('removed:',len(d['edges_removed']))"
```
判据：`removed: 1`。（恢复把 `false` 改 `true` 再发一次）

### A2 · 算路下发（FR-06~08）

```bash
curl -s -X POST localhost:8000/api/route -H 'Content-Type: application/json' \
  -d '{"src":"10.0.0.1","dst":"10.0.0.3"}'
```
然后在 Mininet 里 `h1 ping -c 3 10.0.0.3`，再 `sudo ovs-ofctl -O OpenFlow13 dump-flows s2`。
判据：`ok:true` + `0% packet loss` + 流表里有对应 `IN_PORT/OUTPUT`。

### A4 · 自适应重算（FR-10）

先按 A2 下发并 ping 通，然后跑 A3 的断链命令，同时在 Mininet 里跑：

```bash
h1 ping -i 0.2 10.0.0.3
```
判据：中断时间 < 10s 后恢复连续回包；`grep recompute` 有记录。

### A5 · 多对隔离（FR-09/11）

先下发两对（`h1→h3`、`h2→h4`），Mininet 里同时 `h1 ping -f 10.0.0.3 &` 和 `h2 ping -f 10.0.0.4 &`；
再 `DELETE /api/route` 删掉第一对。
判据：第一对断，第二对**不掉一个包**。

### A6 · 组播（FR-15/16）

两个接收者 `h3`、`h4` 上各跑 `nc -u -l 5000`，源 `h1` 上 `echo hi | nc -u 224.0.0.1 5000`（或 `iperf -u -c 224.0.0.1`）。
判据：两个终端都打印 `hi`；`sudo ovs-ofctl -O OpenFlow13 dump-groups s1` 有 `group_id`。

## 5. 演示边界（诚实清单）

现场**能**演示：拓扑感知、断链 diff、算路下发、断链自愈、多对隔离、组播、前端实时刷新。

现场**不**演示（有替代证据）：

| 项 | 为什么不演 | 替代证据 |
|---|---|---|
| 主机迁移（FR-05） | 要在 Mininet 里重建 veth，失败率高、耗时长 | 单元测试输出（两份 hosts.json 对比） |
| IGMP 自动感知 | 属明确裁剪范围（1.2 表） | 说明「用 REST 手动注册保底」的设计取舍 |
| 1000 轮内存稳定（NF-05） | 要跑 80 分钟 | 200 轮实测曲线 + 说明 |
| ONOS 重启自愈（NF-03） | 现场重启 Controller 风险高 | 提前录屏 30 秒 |
