> **这是三人协作的唯一事实来源（N3 冻结件）。** 代码和本文档不一致 → 先改文档，再改代码，并在群里通知。
> 图例：✅ = 本项目已实测确认 ｜ 📖 = 实验书原文/示例 ｜ ❓ = 尚未实测，不许当结论用

## 0. 冻结规则

| 项 | 内容 |
|---|---|
| 冻结条件 | **N3 闸门通过当天**（部分函数可提前冻结，标注「已冻结」） |
| 冻结范围 | 全部函数签名、出参结构、HTTP API 路径与字段、错误约定 |
| 冻结后允许 | **只加不改**：可以新增函数、新增可选字段、新增接口 |
| 冻结后禁止 | 改已有函数的入参/出参、改字段名、改 `diff` 的 key、改嵌套层级 |
| 改的流程 | 先提 PR 改本文档 → 标题写 `02 变更：xxx 从 A 改成 B` → **48 小时内无异议即生效** → 再动代码 |

**但第 4 节（数据结构）与第 1 节（环境常量）可以更早冻结，不必等 N3。**
理由：它们是**格式契约**。乙丙不需要等真实 ONOS 响应，按第 4 节的字段手写 fixture 就能开工。
真样本到位后替换 fixture，测试代码不用改。详见 `05_异步协作约定` 第 2 节。

**为什么 §4 的数据结构比 §3 的函数签名更硬**：函数签名改了只影响调用点（编译器/报错会告诉你），
数据结构字段改了是**静默失效**——`diff` 里 `edges_removed` 改名成 `removed_edges`，
乙的代码不会报错，只会永远筛出零条受影响路径，然后你在演示现场看着 ping 不通。

## 2. ONOS 北向 REST 端点

统一请求头：

```python
headers = {"Accept": "application/json", "Content-Type": "application/json"}
auth    = HTTPBasicAuth("karaf", "karaf")
```

| # | 方法 | 路径 | 用途 | 状态 |
|---|---|---|---|---|
| 1 | GET | `/devices` | 全部交换机 | ✅ |
| 2 | GET | `/hosts` | 全部主机（含 IP、位置） | ✅ |
| 3 | GET | `/links` | 全部链路（**双向各报一次**） | ✅ |
| 4 | GET | `/flows/{deviceId}` | 某交换机流表 | 📖 |
| 5 | POST | `/flows/{deviceId}?appId={APP_ID}` | 下发流表（**appId 在 query，不在 body**） | 📖 |
| 6 | DELETE | `/flows/{deviceId}/{flowId}` | 精确删一条 | 📖 |
| 7 | POST | `/devices/{id}/portstate/{portId}` | 制造/恢复链路故障，body `{"enabled": false}` | 📖 |
| 8 | GET | `/devices/{id}/ports` | 端口列表（可选，做端口名展示才需要） | ❓ |

**禁用**：`DELETE /flows/application/{appId}`（会删光所有通信对的流表）。

### 2.1 `/devices` 响应（✅ 结构，❓ 具体字段以实测为准）

```json
{
  "devices": [
    {
      "id": "of:0000000000000001",
      "type": "SWITCH",
      "available": true,
      "role": "MASTER",
      "mfr": "Nicira, Inc.",
      "hw": "Open vSwitch",
      "sw": "2.17.12",
      "driver": "ovs",
      "chassisId": "1",
      "annotations": {"managementAddress": "..."}
    }
  ]
}
```

用到：`id`（dpid）。`available=false` 的交换机**不要**放进 graph。

### 2.2 `/links` 响应

```json
{
  "links": [
    {
      "src": {"device": "of:0000000000000001", "port": "2"},
      "dst": {"device": "of:0000000000000002", "port": "1"},
      "type": "DIRECT",
      "state": "ACTIVE"
    },
    {
      "src": {"device": "of:0000000000000002", "port": "1"},
      "dst": {"device": "of:0000000000000001", "port": "2"},
      "type": "DIRECT",
      "state": "ACTIVE"
    }
  ]
}
```

**⚠ 一条物理链路出现两次**（A→B 与 B→A）。存图时有向各存一条是**对的**（端口信息不同），
但做 diff 时必须 `frozenset({src_device, dst_device})` 归一化，否则 `edges_added` 会翻倍。

`state != "ACTIVE"` 的链路**不要**加进 graph（这就是断链后重算的触发点）。

### 2.3 `/hosts` 响应

```json
{
  "hosts": [
    {
      "id": "00:00:00:00:00:01/None",
      "mac": "00:00:00:00:00:01",
      "vlan": "None",
      "ipAddresses": ["10.0.0.1"],
      "locations": [{"elementId": "of:0000000000000001", "port": "1"}],
      "configured": false,
      "suspended": false
    }
  ]
}
```

**三个坑：**

1. `id` 是 `MAC/VLAN`，**不是 IP**。IP 在 `ipAddresses[0]`。
2. `ipAddresses` 可能是 `[]` —— 主机还没发过包。→ **必须先 `pingall` 再拉拓扑**，代码里对空 IP 打 WARNING。
3. 判断主机是否迁移，`elementId` 和 `port` **两项都要比**。

### 2.4 下发流表（POST）

请求体（📖 实验⑦ 5.2.2）：

```json
{
  "priority": 40000,
  "timeout": 0,
  "isPermanent": true,
  "deviceId": "of:0000000000000001",
  "selector":  {"criteria": [{"type": "IN_PORT", "port": "1"}]},
  "treatment": {"instructions": [{"type": "OUTPUT", "port": "2"}]}
}
```

URL：`POST /onos/v1/flows/of:0000000000000001?appId=org.sdn.brain`
→ appId 是 **query 参数**，写进 body 无效。

响应体（❓ **未实测**）：预期形如 `{"flows":[{...,"id":"123"}]}`。
**这是 M2 阶段必须实测的第一件事**，因为删除流表要用这个 `id`。
若响应不带 id，退路：POST 后立刻 `GET /flows/{deviceId}?appId=org.sdn.brain` 反查，按 `selector+treatment` 匹配出 id。

### 2.5 删除流表

`DELETE /onos/v1/flows/{deviceId}/{flowId}` → 成功 200/204。没有通配删除。

### 3.5 `path.py` ｜ 乙

```python
    #                              # out_ports[i] = 从 path[i] 发往 path[i+1] 的端口

    # 空 dict 表示无需求或不可达
```

**端口语义（极易搞错，务必对齐）：**
- `path[i]` 上的 `out_ports[i]` 来自 `graph[path[i]][path[i+1]]["sport"]`
- `path[i]` 的入端口 = `path[i-1]` 的 `out_ports[i-1]`（`i>0`），首跳入端口来自主机的 `host_table` 位置

## 4. 数据结构（内存态，全组共用定义）

### 4.1 拓扑图 `graph`

```python
{
  "of:0000000000000001": {
      "of:0000000000000002": {"sport": 1, "dport": 2, "weight": 1},
  },
  "of:0000000000000002": {
      "of:0000000000000001": {"sport": 2, "dport": 1, "weight": 1},
  },
}
```
**有向**。`sport` = 从键节点出发的端口；`dport` = 对端接收端口。

### 4.2 主机表 `host_table`

```python
{ "10.0.0.1": {"dpid": "of:0000000000000001", "port": 1, "mac": "00:00:00:00:00:01"} }
```

### 4.3 快照 `snapshot`

```python
{
  "nodes": {"of:0000000000000001", "of:0000000000000002"},
  "edges": {frozenset({"of:...0001", "of:...0002"})},       # 无向归一化
  "hosts": {"10.0.0.1": ("of:...0001", 1)},                 # 位置含端口
}
```

### 4.4 下发记录 `deployed`

```python
{
  ("10.0.0.1", "10.0.0.4"): {
      "path":     ["of:...0001", "of:...0004"],
      "out_ports":[2],
      "flow_ids": [("of:...0001", "123"), ("of:...0004", "456")],
      "installed_at": 1730000000.0,
  }
}
```
**key 是 (源IP, 目的IP) 元组。** 删除必须逐条按 `flowId` 精确删。

## 5. 轮询主循环（甲实现，乙丙依赖其数据新鲜度）

```python
async def poll_loop(app):
    prev = topo.empty_snapshot()
    while True:
        try:
            devs, links, hosts = await asyncio.gather(
                onos_async.fetch_devices(),
                onos_async.fetch_links(),
                onos_async.fetch_hosts(),
            )
            graph, ht = topo.build_graph(links), topo.build_host_table(hosts)
            cur = topo.make_snapshot(graph, ht)
            d = topo.diff(prev, cur)

            if d["changed"]:
                app.ctx.graph, app.ctx.host_table = graph, ht
                app.ctx.snapshot, app.ctx.last_diff = cur, d
                prev = cur
                await push_ws(app, {"type": "topo", "diff": d, "graph": graph, "hosts": ht})
                keys = flow.affected(d, app.ctx.deployed)      # 乙提供
                if keys:
                    flow.recompute(keys, graph, ht)
        except OnosError as e:
            app.ctx.onos_errors += 1
            app.ctx.last_error = str(e)
            log.warning("poll failed: %s", e)          # 不 break，不退出
        await asyncio.sleep(POLL_INTERVAL)
```

**硬要求：ONOS 挂掉、网络断了，大脑不能崩。** 捕获一切异常，打日志，继续下一轮。

### 6.1 `/api/state` 完整字段（**字段存在的原因 = 某条 NF 要验它**）

| 字段 | 类型 | 为什么必须有 | 对应 |
|---|---|---|---|
| `graph` | dict | 邻接表全量 | FR-02 |
| `hosts` | dict | 主机表全量 | FR-03 |
| `paths` | list | 已下发通信对摘要（来自 `deployed`，不含 flowId 列表） | FR-08/09 |
| `last_diff` | dict | 最近一次 `diff` 全量 | FR-04 |
| `last_poll_ts` | float | 上一轮轮询成功的时间戳 → **算感知延迟** | NF-01 |
| `poll_count` | int | 累计成功轮数 → 证明「真的在周期跑」 | NF-01 |
| `poll_ms` | int | 上一轮耗时 → 证明异步没被阻塞 | NF-04 |
| `onos_ok` | bool | 当前控制器可达性 | NF-03 |
| `onos_errors` | int | 累计失败次数 → 控制器挂掉时递增，恢复后不再增 | NF-03 |

## 7. 错误与日志约定

```python
log = logging.getLogger("brain.<模块名>")
```

| 场景 | 处理 |
|---|---|
| REST 非 2xx | 抛 `OnosError(status, body[:200])`；轮询里捕获并计数 |
| REST 超时 | 同上，`status=None` |
| `hosts` 里 IP 为空 | `log.warning`，跳过，不进 host_table |
| 路径不可达 | 返回 `None` / `{"ok": false}`，**不要抛异常** |
| 下发流表失败 | 回滚：把已下发的 flowId 全部删掉，`log.error` |
| group 命令失败 | 返回 `False` + `log.error(stderr)` |

日志格式：`%(asctime)s %(levelname)s [%(name)s] %(message)s`

## 8. 变更流程

1. 想改接口 → **提 PR 改本文档**，PR 标题写 `02 契约变更：xxx 从 A 改成 B`，描述里写清影响谁的代码。
2. 拉另外两人 review。**48 小时内**无人反对即生效；有人反对就在 PR 里讨论出结论，不上群聊。
3. **被卡死时的口子**：可以不改就没法继续干活 → 先按自己方案写代码，但必须在 PR 里写明
   「按 X 方案先做了，不同意请明天内提出」。**不许默默改**。
4. 严禁「代码先改了、文档不补」——三个人并行时这会直接导致联调失败，而且是**静默**失败（见 §0）。

> 完整的分支、PR、评审时效、无人值守兜底见 [`05_异步协作约定`](05_异步协作约定.md)。
