# 三人分工与开发计划（闸门制 v2）

> **v2 改动**：废弃 v1 的 `M1–M5` 时间里程碑，改用 `N0–N7` 产出闸门。
> 原因：时间里程碑问的是「到日子了做完了吗」，闸门问的是「这个产出真的成立吗」。
> 上一轮返工的教训（一次造 40 个文件、全是黑盒、连续误判四次）本质就是**没有闸门**。
>
> 目标：**11/15 前功能跑通 + 演示材料成型**（避开 11/21 的编译原理 + 概率论半期考）。

### 1.2 各闸门的通过标准

**N0 / N1（`04` 已完成初稿，需三人各读一遍）**
- [ ] 「不做什么」里每一条都是**想过并决定不做**的，不是漏的
- [ ] 每条 FR 都写了判据；写不出判据的 = 没想清
- [ ] 每条 NF 都被问过「这条要接口支持吗」，答「要」的已落进 `/api/state` 字段表
- [ ] 编号一次定死，此后只增不改

**N2（数据结构 + 真实样本）**
- [ ] `samples/devices.json` / `links.json` / `hosts.json` 三份**真实响应**已落盘（不是手编的）
- [ ] 用真样本跑一次 `build_graph`，节点数 == 交换机数
- [ ] 用真样本跑一次 `build_host_table`，主机数 == `pingall` 的主机数
- [ ] 手造一份删掉一条边的 `links_broken.json`，`diff` 的 `edges_removed` **长度 == 1**（不是 2）
- [ ] 四个结构的字段名写进 `02` 并冻结

**N3（接口契约冻结）** ← 流程文档里最狠的一条：**前后端各派一人照清单写调用示例**
- [ ] 乙照 `02` 写一个 `path_to_flows` 的假数据调用（不依赖真实 ONOS），能跑出 `[(dpid, flow)]`
- [ ] 丙照 `02` 写一个 `/api/route` 的假数据响应，前端能吃下去
- [ ] 两人对不上 = 清单有歧义，**当场改 02，不是改代码**
- [ ] 冻结后：**加接口可以，改已有接口的入参/出参不行**

**N4（骨架贯通）**
- [ ] 找一个**没参与搭建的人**（另一名组员，或让 AI 照 README 盲跑）从头跑通，全程不问
- [ ] 判断跑通看 `curl /api/state` 的字段，**不看启动日志**（Sanic 打印「启动成功」时 ONOS 可能根本没连上）
- [ ] `README` 里每条命令你自己从头敲过一遍

**N5（核心闭环）**
- [ ] `fwd` 已关（关掉后网络立刻不通，这是判据）
- [ ] 从 `ping` 不通到 `ping` 通，全程可重复三次
- [ ] `dump-flows` 与 `deployed` 表能对上

**N6（边界与故障专项）** ← 只实测，不推理（见第 3 节口径 8）
- [ ] `docker stop onos` 60s → 进程不崩 → `docker start` 后 15s 内自愈
- [ ] 拓扑全断（删掉所有链路）→ 算路返回「不可达」而不是抛异常
- [ ] 同一对重复下发 3 次 → 不产生同 `IN_PORT` 同 `priority` 冲突规则，`dump-flows` 条数不翻倍
- [ ] 两对主机**同时**下发 → `deployed` 不串
- [ ] 下发中途 ONOS 挂掉 → 已下的流被回滚删除，不留半条路径
- [ ] 主机无 IP（没 `pingall`）→ 打 WARNING 且不崩
- [ ] 组播空需求集合 → 返回空而不是起 group

**N7（交付收口）**
- [ ] 按演示脚本从零跑一遍，卡壳处当场改 README
- [ ] 演示数据含**故障样本**：正常通 / 断链 / 不可达，让评审能当场验规则
- [ ] 此后不再动 `02` 的结构定义

## 2. 对参考流程的取舍（砍了什么、为什么）

| 流程文档里的项 | 我们的处理 | 理由 |
|---|---|---|
| N0 范围冻结 | **全采纳**，已写入 `04` | 我们原来只有功能列表，没有「不做什么」——这是最大的漏洞 |
| N1 FR/NF 表 | **全采纳**，14 条 FR + 7 条 NF | 原计划 NF 一条没有，「5 秒感知」「控制器挂了不崩」全靠嘴说 |
| N1 需求追溯表 | **砍** | 只服务评审，不服务开发 |
| N2 ER 图 + 建表 SQL | **改造**为「内存四结构 + 真实样本落盘 + 干净数据跑一次」 | 无数据库，等价物是 `graph/host_table/snapshot/diff` 和 ONOS 真实响应 |
| N2 外键/删除策略 | **改造**为「流表删除策略」：按 `flowId` 精确删、先下新再删旧、`deployed` 先写后删 | 没有行级引用，但有「流与图的引用关系」，本质同一件事 |
| N3 接口契约冻结 | **全采纳**，且加「乙丙各写一个调用示例」这道闸 | 三人并行唯一有效的防歧义手段 |
| N3 认证/令牌 | **改造**为「明确不做认证」写进 N0 | 是裁剪决策，不是遗漏 |
| N4 骨架贯通 | **全采纳** | 「别人照 README 盲跑」比原来的「跑通了」严得多 |
| N5 核心闭环 | **全采纳** | 原计划把前端放最后，实际风险在「下发失败回滚」，要提前 |
| N6 并发/越权专项 | **改造**为「控制器故障 + 拓扑退化 + 重复下发 + 下发中崩溃」 | 无多用户无越权；但「下发中途控制器挂了」比并发问题更致命 |
| N7 交付收口 | **全采纳** | 已有演示六步，补「含故障样本」 |
| DFD / 用例 9 字段 / 13 维评分表 | **砍** | 结构化分析产物，与契约文档重复表达同一件事 |
| md/docx/xlsx 三格式并存 | **砍**（坚持 Markdown 单份） | 就是流程文档自己列的反模式第 1 条 |
| 六套编号体系 | **砍**，只留三套：`FR-xx` / `NF-xx` / 接口名 | 一致性维护成本会爆炸 |

## 3. 十条硬口径（开写代码前一次定死）

1. **链路归一化口径**：`frozenset({u, v})` 只在 `topo.diff` 里出现**一次**。
   其他文件不许自己写去重逻辑。写第二处 = 两处口径迟早分叉。
2. **常量一套**：`APP_ID` / `POLL_INTERVAL` / 流表 `priority` / `group_id` 只在 `config.py`。
   前端不许自己推 dpid 尾号规则，要用后端下发的 `label`。
3. **编号只留三套**：`FR-xx`（功能）、`NF-xx`（非功能）、接口用**名字**不用编号。
4. **接口必须覆盖 NF**：`/api/state` 的字段由 `04` 第 3.1 节反推而来。
   新增 NF 时先问「要什么字段才能验」，再决定加不加接口。
5. **流表删除策略现在定死**：按 `flowId` 精确删；`deployed` 必须在**下发成功返回后**才写；
   改写路径时**先下新再删旧**；下发中途失败必须回滚已下的流。
6. **凭据集中**：`ONOS_USER/PASS` 只在 `config.py` 出现一次。它是实验环境默认口令，不是秘密，
   但代码里出现第二处就是隐患（换环境必漏改）。
7. **不做鉴权**：`/api/*` 无令牌、前端无登录。写进 N0「不做什么」，此后不再讨论。
8. **并发口径**：Sanic **单进程单事件循环**。由此推出三条铁律：
   - `app.ctx.graph` / `snapshot` / `deployed` **只能整体替换引用，禁止原地修改**
     （轮询协程写、HTTP 处理器读，原地改会让读方看到半成品）
   - 协程里所有 REST 调用必须 `await`（`aiohttp`），**禁止在 `async def` 里调 `requests`**
   - 结论**以实测为准，不以机制推断为准**：单进程下「会不会竞态」要测，别拍脑袋
9. **冻结时间点写死**：**11/2 之后 `02` 只增不改**；`topo.diff` 字段名此后不许动，
   连「加一个字段」也算改动，要全员确认。
10. **单实现原则**：一个文件只有一个作者。`graph` 的构造只有 `topo.build_graph` 一条路径。

## 7. 联调 SOP（三终端，一次只敲一条）

**终端 A —— ONOS**
```bash
docker ps --filter name=onos
```

**终端 B —— Mininet（必须在 ONOS 之后起）**
```bash
sudo mn -c
sudo mn --topo=tree,2,2 --controller=remote,ip=127.0.0.1,port=6653 --mac --switch=ovs,protocols=OpenFlow13
```
进去后 `pingall` —— **不做这步 `hosts` 的 `ipAddresses` 是空的**，主机构建不出来。

**终端 C —— 大脑**
```bash
cd ~/sdn-brain && python3 main.py
```

**关 `fwd`（每次容器重启后要重做）**
```bash
ssh -p 8101 karaf@localhost -o HostKeyAlgorithms=+ssh-rsa     # 密码 karaf
app deactivate org.onosproject.fwd
app list | grep fwd
```
**验证真关掉了**：此时网络应该立刻不通。还通 = 没关干净，后面所有结果都不可信。

**演示六步（N7 用）**
1. `pingall` 全通（`fwd` 开着，走传统转发）
2. 关 `fwd` → `pingall` 全失败 → **证明 SDN 接管了转发**
3. 起大脑 → 前端画出拓扑
4. 前端选 `h1 → h3` → 计算下发 → `ping` 通 → `dump-flows` 展示
5. `portstate {"enabled":false}` 断链 → 10s 内 `ping` 自愈 → 日志展示 `recompute`
6. 组播：源 + 两接收者 → `dump-flows` 展示 `group`

## 8. 防冲突规则

| 规则 | 说明 |
|---|---|
| **文件所有权** | 谁负责的文件谁改。别人需要改动 → 提需求，不自己动手 |
| **单实现原则** | 同一模块不许两条线并行做再合并（纯损耗，还会产生重名文件） |
| **接口变更** | 先改 `02` → 群里发一句 `02 变更：xxx 从 A 改成 B` → 30 分钟无异议才动代码 |
| **不许静默改字段** | 改 `diff` 的 key 名、改 `graph` 嵌套层级 = 直接引爆另外两人的代码 |
| **共享文件** | `config.py` 只有甲改；`02` 谁都能提修改但要全员确认 |

## 10. 给 AI 助手的协作约定（三个人各自看）

1. **一次只推进一步**：给 1–3 条命令，等人贴输出再走下一步。不许一次丢一堆脚本。
2. **不许编结论**：没实测的标 `❓待确认`，不许在报告里写成事实。
3. **报错先看原文**：401 / 404 / 500 含义完全不同，先看状态码和响应体，不要猜。
4. **改代码前先读 `02`**，确认改的接口没破坏别人的调用。
5. **不生成 `.sh` / 批量文件**——本项目吃过「一次造 40 个文件、全是黑盒」的亏。
6. **区分「服务器说了什么」和「我以为是什么」**。
