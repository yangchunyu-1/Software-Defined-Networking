## 记录

```
【#1 控制器故障自愈】  （丙用 mock 代测，真控制器这一段仍归甲）
日期：2026-11-19
负责人：丙（HTTP 层观测）+ 甲（真 ONOS 复测）
命令：
  cd brain && ./run.sh demo --no-keep        # 起 mock ONOS + 大脑（同进程内后续用下面两步代替 demo）
  python tools/mock_onos.py &  python main.py &
  curl -X POST localhost:8181/_mock/down -d '{"down":true}'    # 等价于所有 /onos/v1/* 返回 503
输出（关键行）：
  故障前: onos_ok=True hosts=6
  故障中: onos_ok=False onos_errors=2 last_error=GET .../devices -> HTTP 503
  进程仍在服务: /api/state 可读，poll_count=2
  恢复耗时: 2.6s  自愈后 onos_ok=True hosts=6
结论：⚠️ 有条件通过
备注：
  · 证明了「ONOS 挂了不崩、onos_errors 递增、last_error 有原文、恢复后自动回到 onos_ok=True」。
  · **没证明**「docker stop 容器后 SSH/REST 端口不再响应」这条路径（那是连接被拒，不是 503），
    也没跑满 60s。真环境复测命令：docker stop onos && sleep 60 && docker start onos，
    然后看 /api/state 的 onos_ok 在 15s 内回到 True。
  · 演示用例：这一条也可以当「控制器故障」的现场演示，因为不依赖 Docker。
```

```
【#6 主机无 IP（没 pingall）】
日期：2026-11-19
负责人：丙
命令：
  python tools/mock_onos.py &  python main.py &
  curl -X POST localhost:8181/_mock/hosts -H 'Content-Type: application/json' -d '{"pingall":false}'
  # 等一轮轮询（POLL_INTERVAL=5s）后：
  curl -s localhost:8000/api/state
  curl -s -X POST localhost:8000/api/route -H 'Content-Type: application/json' \
       -d '{"src":"10.0.0.1","dst":"10.0.0.3"}'
  grep "ipAddresses is empty" .run/brain.log
输出（关键行）：
  hosts 6 graph 4 onos_ok True            # 正常
  hosts 0 graph 4 onos_ok True poll_count 3   # ipAddresses 全空后
  {"ok":false,"error":"unknown_host"}  <HTTP 404>
  6 条 WARNING [brain.topo] skip host ...: ipAddresses is empty (run pingall first)
结论：✅ 通过（HTTP 层）
备注：
  · 判据「打 WARNING 且不崩」成立：6 台主机全部跳过、主机表清空，但轮询继续、HTTP 正常、进程没退。
  · 路由请求返回 404 + `unknown_host` 而不是 500/异常，调用方能看懂「先去 pingall」。
  · 真环境复测：`sudo mn -c && sudo mn ...` 之后**不要** pingall，直接 `./run.sh smoke`
    看「主机表 为空」那行 FAIL。
```
