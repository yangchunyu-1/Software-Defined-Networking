## 记录

```
【#6 主机无 IP（没 pingall）】
日期：2026-11-19
负责人：丙
环境：真实 ONOS 2.7.0 容器 + WSL Ubuntu-24.04 上 Mininet tree,2,2（3 交换机）
命令：
  sudo mn --topo=tree,2,2 --controller=remote,ip=127.0.0.1,port=6653 \
           --mac --switch=ovs,protocols=OpenFlow13      # 起来后**不执行 pingall**
  python3 main.py &
  curl -s localhost:8000/api/state
  curl -X POST localhost:8000/api/route -H 'Content-Type: application/json' \
       -d '{"src":"10.0.0.1","dst":"10.0.0.4","both":true}'
  grep -c 'ipAddresses is empty' brain.log
输出（关键行）：
  switches 3 hosts 0 onos_ok True poll_count 2
  POST /api/route -> HTTP 404
  {"ok":false,"error":"unknown_host"}
  再次 GET /api/state -> HTTP 200（进程还活着）
  WARNING 条数: 0
  —— 之后 pingall → Results: 0% dropped (12/12)，switches 3 hosts 4
结论：✅ 通过（判据需修订）
备注：
  · 「不崩 + 返回 unknown_host」这两半成立：轮询继续（poll_count 递增）、HTTP 正常、
    路由接口给的是 404 而不是 500/异常，调用方能看懂「先去 pingall」。
  · **「打 WARNING」这半在真实 ONOS 上走不到**：没 pingall 时 `/hosts` 直接返回 0 条，
    不是「返回一批 ipAddresses 为空的主机」，所以 topo.build_host_table 的
    WARNING 分支没有对象可打。
  · 建议把 03 的判据改成：「hosts 为空 → `/api/state.hosts` 为 {}、`POST /api/route`
    返回 404 unknown_host、进程不崩」；WARNING 保留给「有主机但 IP 缺失」的场景，
    那需要手改 /hosts 才能造，不适合当验收项。
```
